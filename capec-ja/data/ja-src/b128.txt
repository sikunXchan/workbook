## 656
name: ボイスフィッシング
description/0: 攻撃者は、利用者からアカウントのパスワードや機微な情報を聞き出す目的で、フィッシング攻撃を使って利用者を標的にする。ボイスフィッシングは、フィッシングのソーシャルエンジニアリング手法の変種であり、攻撃が電子メールではなく、音声での電話を通じて開始される点が異なる。利用者は、申告された組織の正当な従業員を装う攻撃者によって、機微な情報を提供するよう誘われる。ボイスフィッシング攻撃は、標準的なフィッシング攻撃とは異なり、利用者が侵害されたWebサイトとやり取りして機微な情報を提供するのではなく、代わりに、その情報を口頭で提供する点が異なる。ボイスフィッシング攻撃は、攻撃者による「コールドコール（無差別電話）」の形で開始されることもあれば、不正な電話番号に電話をかけた被害者によって開始されることもある。
alternate_terms/0/term: ビッシング
alternate_terms/1/term: VoIPフィッシング
execution_flow/0/description/0: ［正規サイトを偽装するためのドメイン名と証明書の取得］この任意の手順は、攻撃者が正当な組織をより説得力を持ってなりすますのを助けるために使用できる。攻撃者は、利用者に、自分が正規のWebサイトを使っていると信じ込ませるため、ホモグラフ攻撃や類似の攻撃を利用できる。攻撃者がこの攻撃のためにコールドコールを利用する場合、この手順は省略される。
execution_flow/0/techniques/0/0: 任意で、正当な組織のドメイン名と見た目が似ているドメイン名を取得する。例として、www.paypaI.com対www.paypal.com（前者は小文字のLではなく、大文字のIを含む）が挙げられる。
execution_flow/1/description/0: ［正規Webサイトの調査と複製の作成］攻撃者は、任意で、なりすまそうとしている組織のWebサイトに近似した（見た目が元のURLと似ているURLに作成されることもある）Webサイトを作成する。そのWebサイトには、被害者の問題を解決するため、そして攻撃を開始するために電話をかけてもらうための電話番号が含まれる。攻撃者がこの攻撃のためにコールドコールを利用する場合、この手順は省略される。
execution_flow/2/description/0: ［利用者をだまして攻撃者に機微な情報を提供させる］攻撃者は被害者に「コールドコール」をかける、あるいは悪意あるサイトを通じて被害者からの電話を受け、利用者に機微な詳細（ログイン認証情報、銀行口座情報など）を攻撃者に提供させるよう説得するため、行動の呼びかけを行う。重要なのは、被害者に、話している相手が、被害者が取引している正当な主体からの者であり、その電話が正当な理由で行われていると信じさせることである。行動の呼びかけは、通常、利用者に行動を促すのに十分なほど正当で緊急性があるように聞こえる必要がある。
execution_flow/2/techniques/0/0: 偽装された、正当に見える電話番号から利用者に電話をかける。
execution_flow/3/description/0: ［盗んだ情報の使用］攻撃者が機微な情報を入手すると、この情報は、被害者の銀行口座にログインして選んだ口座にお金を転送する、あるいは盗んだクレジットカード情報で不正な購入を行うために利用され得る。
execution_flow/3/techniques/0/0: 被害者が提供した認証情報を使って、正規のサイトにログインする。
prerequisites/0/0: 攻撃者は、被害者との最初の接触を開始するための電話番号に加えて、被害者に電話をかけるための、正当に見える電話番号を必要とする。
prerequisites/3/0: 偽装されたWebサイトを通じてこの攻撃を受動的に行う場合、複製されたWebサイトは元のWebサイトと極めて似ている必要があり、そのWebサイトにアクセスするために使われるURLは、該当する事業者の本物のURLのように見える必要がある。
resources/0/0: 被害者との電話を開始するための、正当に見える電話番号。
indicators/0/0: 自分が顧客でもない主体から、アカウントにログインするよう求める電話がかかってくる。
indicators/1/0: 機微な情報の提供を求める、いかなる電話も受ける。
indicators/2/0: 画面上の行動の呼びかけに対応するため、画面上の番号に電話をかけるよう指示するWebサイトへリダイレクトされる。
mitigations/0/0: 未知の番号や、スパムとしてフラグ付けされる可能性のある番号からの電話を受けないこと。また、予期せず悪意ある可能性のあるWebサイトへリダイレクトされた後、画面に表示される番号に電話をかけないこと。いずれの場合も、正当に開始されたものではない音声電話で、機微な情報を提供しないこと。代わりに、銀行、PayPal、eBayなどには、それらの公式Webサイトに記載されている番号を通じて電話をかけ、問題について問い合わせること。
examples/0/0: 標的は、自分のApple IDが不審な活動のために無効化された、そして含まれているリンクには、Appleアカウントのロックを解除する方法についての手順が含まれていると述べる、電子メールやテキストメッセージを受け取る。そのテキストメッセージ内のリンクは正当なものに見え、そのリンクがクリックされると、利用者は、ロック解除処理を開始するため指定された番号に電話をかけるよう求める、正当に見えるWebページへリダイレクトされる。標的は電話をかけ、Appleで働いていると思い込んでいる人物に、自分の認証情報やその他の機微な情報を提供する。攻撃者がこのデータを所有すると、そのアカウントにログインし、Apple Payの情報のような他の機微なデータを得るために使用できる。
examples/1/0: 攻撃者は標的に電話をかけ、その銀行で働いていると主張する。攻撃者は、標的に、潜在的な不正利用の疑いにより銀行口座が凍結されていること、そしてアカウントを再度有効化するには認証が必要であることを伝える。標的は、電話をかけてきた人物が正当な銀行の従業員であると信じ、自分がそのアカウントの認可された所有者であることを確認するため、銀行口座のログイン認証情報を提供する。攻撃者は、その後、この認証を確認し、アカウントのロックが解除されたと主張する。攻撃者がこれらの認証情報を入手すると、被害者のアカウントから、攻撃者が管理するアカウントへお金が転送され得る。
s.summary: フィッシング攻撃を電子メールではなく「電話」で行う変種。利用者を偽のWebサイトに誘導して「困りごとを解決するためにはこちらに電話してください」と番号を提示する、あるいは攻撃者自身が被害者に直接電話をかける（コールドコール）ことで、口頭で認証情報を聞き出してしまう。偽のURLをあらかじめ用意する点は通常のフィッシングと似ているが、最終的に情報を聞き出す手段が「電話での会話」である点が異なる。
s.term: コールドコール, cold call, 事前の関係や依頼がないまま、一方的にかける電話のこと。
s.fact: ボイスフィッシング攻撃は、標準的なフィッシング攻撃とは異なり、利用者が侵害されたWebサイトとやり取りして機微な情報を提供するのではなく、代わりにその情報を口頭で提供する、と原典に書かれている。, CAPEC-656 説明
s.analogy: 「お荷物に不審な点がございますので、こちらの番号にお電話ください」という偽の配送通知を送り、電話をかけてきた相手から口頭で個人情報を聞き出してしまうのに似ている。

## 657
name: 偽装を通じた悪意ある自動ソフトウェア更新
description/0: 攻撃者は、クライアントをだまして、悪意ある提供元からの自動ソフトウェア更新を実行させるため、身元、あるいはコンテンツの偽装を使用する。偽装を利用する悪意ある自動ソフトウェア更新には、コンテンツや身元の偽装だけでなく、プロトコルの偽装も含まれ得る。コンテンツや身元の偽装攻撃は、正当な更新提供元を装う悪意あるWebページ内に、スクリプト化された仕組みを埋め込むことで、ソフトウェアの更新を引き起こすことができる。スクリプトの仕組みは、ソフトウェアの構成要素と通信し、攻撃者のサーバーによって指定された場所からの更新を引き起こす。その結果、クライアントは、正当なソフトウェアの更新が利用可能であると信じるが、代わりに、攻撃者からの悪意ある更新をダウンロードしてしまう。
examples/0/0: 偽装戦略の一例として、eTrust Antivirus Webscan Automated Update Remote Code Executionの脆弱性（CVE-2006-3976、CVE-2006-3977）が挙げられる。この脆弱性では、ActiveXコントロールが、攻撃者が管理するWebページによって遠隔から操作され、完全性の検証を行わずに、攻撃者のコードをダウンロード・実行させることができた。
s.summary: 悪意ある手動ソフトウェア更新（CAPEC-533）とは異なり、利用者の操作を必要とせず、ソフトウェアの「自動更新」機能そのものを偽装のターゲットにする攻撃。正規の更新提供元を装う仕組みをWebページ内に埋め込み、ソフトウェアに悪意ある更新先を信じ込ませてしまう。実例として、ActiveXコントロールを悪用した、eTrust Antivirusの実際の脆弱性（CVE-2006-3976、CVE-2006-3977）が挙げられている。
s.term: ActiveX, ActiveX, 主にInternet Explorer向けに開発された、Webページ上でネイティブコードを実行できるようにする、Microsoftの技術のこと。
s.fact: eTrust Antivirus Webscan Automated Update Remote Code Executionの脆弱性では、ActiveXコントロールが、攻撃者が管理するWebページによって遠隔から操作され、完全性の検証を行わずに攻撃者のコードをダウンロード・実行させることができた、と原典の具体例に書かれている。, CAPEC-657 examples（具体例）
s.analogy: 正規の配送業者の制服とトラックを偽装し、「本日の定期配送です」と言って、注文していない荷物（悪意あるソフトウェア更新）を受取人に自動的に受け取らせてしまうのに似ている。
