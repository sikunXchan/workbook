## 148
name: コンテンツの詐称
description/0: 攻撃者は、コンテンツの一見した出所を変えないまま、元のコンテンツ作成者が意図したものとは異なる内容を含むように、コンテンツを改変する。「コンテンツの詐称」という用語は、標的がホストするWebページを改変して、所有者のコンテンツの代わりに攻撃者のコンテンツを表示させることを指して使われることが最も多い。しかし、コンテンツであれば何であれ詐称の対象となり得る。電子メールの内容、ファイル転送、その他のネットワーク通信プロトコルの内容も含まれる。コンテンツは、その出所（例：Webページの元のファイルを改変する）で改変されることもあれば、転送中（例：送信者と受信者の間のメッセージを傍受して改変する）に改変されることもある。通常、攻撃者はコンテンツが改変されたという事実を隠そうとするが、Webサイトの改ざん（デフェイス）のように、それが必要ない場合もある。コンテンツの詐称は、マルウェアへの感染、（コンテンツが金融取引を扱う場合の）金融詐欺、プライバシー侵害、その他望ましくない結果につながり得る。
prerequisites/0/0: 標的がコンテンツを提供しているが、改変からそれを十分に保護できていないことが必要である。攻撃者は、権限のないデータを改変する手段を持っている必要がある。転送中のコンテンツを改変する場合、攻撃者は狙った通信を傍受できる必要がある。
resources/0/0: 転送中のコンテンツを改変する場合、攻撃者は、標的の通信を傍受し、通信に影響を与えるための独自のパケットを生成・作成できるツールを必要とする。
resources/0/1: いくつかの変種では、標的となるコンテンツの全部または一部が、攻撃者が公開するコンテンツへ誘導されるように改変される（例えば、標的のWebサイトにある画像やフレームが、攻撃者の管理する場所から読み込まれるように改変されることがある）。このような場合、攻撃者は、差し替え用のコンテンツをホストするために必要な資源を必要とする。
consequences/0/note/0: コンテンツの詐称攻撃が成功すると、アプリケーションのデータの完全性が損なわれる。
s.summary: Webページやメールなど、見た目の出所はそのままに、中身だけをすり替えてしまう攻撃の大もとの型（メタ）。利用者は「いつものサイト・いつもの送信者」だと思い込んだまま、すり替えられた内容を信じてしまう。
s.term: 改ざん（デフェイス）, defacement, Webサイトの見た目を攻撃者が勝手に書き換えてしまうこと。コンテンツの詐称の一種だが、隠す必要がない点が特徴的である、と原典に書かれている。
s.fact: 通常、攻撃者はコンテンツが改変された事実を隠そうとするが、Webサイトの改ざんのように、それが必要ない場合もある、と原典の説明に書かれている。, CAPEC-148 説明
s.analogy: 新聞の発行元の名前やロゴはそのままに、記事の内容だけをすり替えてしまうのに似ている。読者は「いつもの新聞だ」と信じて読むため、記事が偽物だとは気付きにくい。

## 149
name: 予測可能な一時ファイル名の探索
description/0: 攻撃者は、標的へのさらなる攻撃を仕掛ける目的で、予測可能な一時ファイルの名前と場所を特定するために標的を調査する。これは、標的アプリケーションが作成する一時ファイルの命名規則と保存場所を分析することを含む。攻撃者が一時ファイルの名前を予測できれば、その情報を使って、情報収集やシンボリックリンク攻撃といった他の攻撃を仕掛けることができる。
prerequisites/0/0: 標的アプリケーションが、例えば連番を増やしていくような、予測可能な手順を使って一時ファイルの名前を付けていることが必要である。
prerequisites/1/0: 攻撃者が、標的が作成しているファイルの名前を見ることができる必要がある。
s.summary: 一時ファイルの名前が予測できるパターンで付けられていないかを調べ、その予測を足がかりに、情報収集やシンボリックリンク攻撃（CAPEC-132）など、次の攻撃につなげるための下調べ。
s.term: 一時ファイル, temporary file, プログラムが処理の途中で、作業用に一時的に作成するファイルのこと。処理が終われば不要になることが多いが、削除されずに残ってしまう場合もある。
s.fact: 攻撃者が一時ファイルの名前を予測できれば、その情報を使って情報収集やシンボリックリンク攻撃を仕掛けられる、と原典の説明に書かれている。, CAPEC-149 説明
s.analogy: ホテルの客室番号が「101、102、103…」のように連番で付けられているのを見て、まだ使われていない予約前の部屋番号を予測してしまうのに似ている。番号の付け方（命名規則）が分かれば、次に現れるものを推測できてしまう。

## 150
name: よくある資源の場所からのデータ収集
description/0: 攻撃者は、標的のセキュリティを損なう目的で、資源が置かれている既知の場所を悪用する。多くの、というよりほとんどのシステムでは、ファイルや資源は既定のツリー構造で整理されている。これは攻撃者にとって有用であり得る。なぜなら、攻撃に必要な資源やファイルをどこで探せばよいか、既に分かっていることが多いためである。狙っている資源の正確な場所が分からない場合でも、命名規則から、標的の機器のファイルツリーのうち、その資源が通常置かれているであろう狭い範囲を示すことができる。例えば、Unix系のシステムでは、設定ファイルは通常/etcディレクトリに保存されている。攻撃者はこれを利用して、他の種類の攻撃を仕掛けることができる。
prerequisites/0/0: 標的アプリケーションが、ファイルが特定の場所にあることを前提としている必要がある。あるいは、ファイルの場所を利用者が設定できる場合であっても、利用者が既定の場所からファイルを移動させなかったか、その種類のファイルに対して慣習的な場所に置いていることが必要である。
resources/0/0: なし：この種の攻撃を実行するために特別な資源は必要ない。場合によっては、攻撃者は、狙った資源が置かれている標的コンピュータ上の場所へ、直接アクセスする必要さえない。
examples/0/0: 攻撃者は、ブルースナーフィング（Bluesnarfing）と呼ばれる手法を使って、データの場所が分かっているBluetooth対応機器からデータを取得できる。これは、機器のOBEX（Object Exchange）Push Profileという機能に接続し、既知のファイル名（連絡先一覧、写真、着信履歴など）に対してOBEXのGET要求を送ることで行われる。ブルースナーフィングは、2003年に発見された直後に修正され、この時期以前またはこの時期に作られた機器でのみ通用する。
s.summary: ファイルや設定情報が、どのシステムでもだいたい決まった場所（例えばUnix系OSの/etcディレクトリ）に置かれがちであることを利用して、見当をつけて情報を探し出す攻撃。正確な場所を知らなくても、よくある命名規則やディレクトリ構成から狙いを絞れる。
s.term: ディレクトリ, directory, ファイルを整理するための「フォルダ」のこと。Unix系OSでは「/etc」のように、スラッシュで区切った道筋（パス）で場所を表す。, 設定ファイルはよく「/etc」というディレクトリに置かれている。
s.fact: 狙っている資源の正確な場所が分からなくても、命名規則から、標的の機器のファイルツリーのうちその資源が通常置かれている狭い範囲を推測できる、と原典に書かれている。, CAPEC-150 説明
s.analogy: 知らない家に忍び込んだ泥棒が、「貴重品はたいてい寝室のたんすの中」という一般的な傾向を知っているため、家中を探し回らずに目当ての場所へ直行できるのに似ている。

## 151
name: 身元の詐称
description/0: 身元の詐称とは、ある（人間または非人間の）実体の身元になりすまし、その身元を使って目的を達成する行為を指す。攻撃者は、別の主体から来たように見えるメッセージを作成したり、盗んだ、あるいは偽装した認証情報を使ったりすることがある。
extended_description/0: あるいは、攻撃者は正当な送信者からのメッセージを傍受し、その内容を変えずに、あたかも自分から送られたメッセージであるかのように見せかけようとすることもある。この後者の形態は、正当な利用者から認証情報を乗っ取るために使われ得る。身元の詐称攻撃は、送信されるメッセージに限られるものではない。身元に結び付いた資源（例えば、署名のあるファイル）であれば何であれ、攻撃者が見かけ上の身元を変えようとする攻撃の標的になり得る。この攻撃は、コンテンツの詐称攻撃とは異なる。コンテンツの詐称では、攻撃者はメッセージの見かけ上の身元を変えたいのではなく、メッセージが伝える内容を変えたいのである。身元の詐称攻撃では、攻撃者はコンテンツの「身元」を変えようとしている。
prerequisites/0/0: メッセージや資源に結び付いた身元が、検知されない形で取り除けるか、改変できることが必要である。
mitigations/0/0: 多要素認証などの、強固な認証プロセスを採用する。
s.summary: 「誰から来たものか」という身元そのものをすり替えてしまう攻撃の大もとの型（メタ）。中身を変えるコンテンツの詐称（CAPEC-148）とは異なり、中身はそのままに、送り主や作成者の見かけを変える点が特徴である。
s.term: 認証情報, authentication credentials, 利用者本人であることを確認するために使われる、パスワードや鍵、証明書などの情報のこと。これを盗まれたり偽装されたりすると、他人になりすまされてしまう。
s.fact: コンテンツの詐称（CAPEC-148）との違いは、コンテンツの詐称がメッセージの内容を変えようとするのに対し、身元の詐称はメッセージの「身元」を変えようとする点にある、と原典に書かれている。, CAPEC-151 説明
s.analogy: 手紙の文章はそのままに、差出人の名前だけを別人の名前に書き換えてしまうのに似ている。受け取った人は、文章の内容ではなく「誰から来たか」という部分で誤解させられてしまう。

## 153
name: 入力データの操作
description/0: 攻撃者は、入力を処理するインターフェースに送るデータの書式、構造、構成を制御することで、入力の検証における弱点を悪用する。標準的でない、あるいは予期しない形式の入力を与えることで、攻撃者は標的のセキュリティに悪影響を及ぼすことができる。
extended_description/0: 例えば、異なる文字エンコーディングを使うことで、危険なテキストが安全なテキストとして扱われてしまうことがある。あるいは、攻撃者はファイル拡張子のような特定のフラグを使って、提供するデータが実際にはその種類ではないにもかかわらず、標的アプリケーションに「このデータは特定の解釈系（インタープリタ）で処理すべきものだ」と思い込ませることがある。これにより、保護機構を回避させたり、標的に入力処理のための特定の構成要素を強制的に使わせたり、その他、利用者のデータが本来想定されていたものとは異なる形で処理されたりする結果につながり得る。この攻撃は、変数操作とは異なる。変数操作は、入力の「値」を通じて標的の処理を乗っ取ろうとするのに対し、入力データの操作は、入力が「どのように処理されるか」を制御しようとするものである。
prerequisites/0/0: 標的が、処理のために利用者のデータを受け付けており、そのデータの処理の仕方が、攻撃者が制御できる書式やフラグの何らかの側面に依存していることが必要である。
s.summary: 入力する「値」そのものではなく、入力の形式やファイル拡張子などの「どう処理すべきかの手がかり」を操作することで、本来とは違う扱いを標的に強制する攻撃の大もとの型（メタ）。
s.term: 文字エンコーディング, character encoding, 文字をコンピュータが扱える数値（バイト列）に変換するための規則のこと。同じ文字でも、使うエンコーディングによって見かけ上の安全性の判定が変わってしまうことがある。
s.fact: この攻撃は、入力の「値」を通じて処理を乗っ取ろうとする変数操作とは異なり、入力が「どのように処理されるか」を制御しようとする点が特徴である、と原典に書かれている。, CAPEC-153 説明
s.analogy: 荷物の中身（値）は変えずに、荷札に書く「取扱注意：冷凍」というラベル（処理のための手がかり）だけを書き換えて、本来とは違う倉庫・違う扱いに回させてしまうのに似ている。

## 154
name: 資源の場所の詐称
description/0: 攻撃者は、アプリケーションや利用者を欺き、意図しない場所から資源を要求するよう仕向ける。場所を詐称することで、攻撃者は、別の資源が使われるように仕向けることができ、その資源はしばしば攻撃者が管理するものであり、攻撃者の悪意ある目的を達成する助けとして使われ得る。
prerequisites/0/0: 前提条件なし。すべてのアプリケーションはファイルパスに依存しているため、理論上、それらやその資源は、この種の攻撃の影響を受け得る。
mitigations/0/0: 異常な、あるいは権限のない通信のやり取りを検知するため、ネットワークの活動を監視する。
s.summary: アプリケーションや利用者に、「本来の場所」ではなく攻撃者が用意した別の場所から資源（ファイルや設定など）を読み込ませてしまう攻撃の大もとの型（メタ）。ファイルパスに依存するアプリケーションであれば、理論上どれも影響を受け得る、と原典に書かれている。
s.term: ファイルパス, file path, ファイルやフォルダの場所を示す道筋のこと。「どこから読み込むか」を指定するために使われる。
s.fact: すべてのアプリケーションはファイルパスに依存しているため、理論上、それらやその資源はこの種の攻撃の影響を受け得る、と原典の前提条件に書かれている。, CAPEC-154 前提条件
s.analogy: 「この商品はいつもの正規の問屋から仕入れてください」と指示されているところに、偽の問屋の連絡先を差し込んで、そちらから仕入れさせてしまうのに似ている。仕入れ先（場所）が入れ替わっただけで、注文の内容自体は変わっていないように見える。
